**FinSignal-Hy3: Financial Anomaly Detection with Omission-Sensitive Evaluation**

> 犀牛鸟开源实战任务 · 题目一
>
> 开放式场景：AI 应用与评判标准设计

## 一、项目概述

### 1.1 一句话描述

输入一家制造业上市公司连续 3～5 年的结构化财务数据，由 Hy3 在不接收规则候选答案的情况下，生成结构化财务异常信号卡片；同时构建一套以“严重异常漏报率”为主指标的混合评估系统，通过财务数据复算、标准异常集合比对、证据核验、注入实验、阴性对照、人工标注和 Hy3 语义评审，验证应用输出质量以及评估器自身的可靠性。

### 1.2 项目要解决的问题

传统财务筛选器可以计算指标并判断是否超过阈值，但难以完成以下开放式工作：

- 判断某个指标触发是否具有实际重要性；
- 综合多个指标发现复合异常；
- 区分数据事实、分析推断和未经验证的可能原因；
- 给出可执行的下一步核查建议；
- 控制结论边界，避免从“关注信号”直接跳到“财务造假”或投资建议；
- 在可选的管理层叙事文本中识别数据与表述不一致的情况。

因此，本项目采用“上层开放、底层可验”的设计：异常解释、优先级和核查建议没有唯一答案，但支撑结论的原始数字、计算公式、异常类型和证据位置可以自动验证。

### 1.3 与任务要求的对应关系

| 任务要求 | 本项目设计 |
|---|---|
| 面向真实用户场景的 AI 应用 | 面向财务学习者、投研实习生和审计辅助人员的异常初筛应用 |
| 输出不存在唯一标准答案 | 信号重要性、替代解释、核查顺序与结论边界属于开放式判断 |
| 至少 5 个评估维度 | 设计 8 个维度，其中客观维度由脚本验证，开放维度由锚点式 rubric 评审 |
| 样本含难例与反例 | 真实窗口、强度梯度注入、阈下阴性对照和对抗输出 |
| 判别力验证 | 好、中、差三档输出的排序准确率与 Kendall’s τ |
| 一致性验证 | 双人标注一致性、自动评分与人工评分相关性、Judge 重复评估波动 |
| 对抗性验证 | 伪造证据、错误公式、术语堆砌、篇幅膨胀、年份错置和过度推断 |
| 完整评测与分析 | 输出主结果表、漏报率曲线、消融实验、典型案例与能力边界 |

### 1.4 核心创新

1. **漏报敏感评估**：不只判断模型报出的信号是否正确，还显式计算它遗漏了哪些标准异常，重点报告严重异常漏报率。
2. **注入元数据作为独立真值**：对注入样本，标准答案来自注入操作记录，而不是模型输出或 Judge 主观判断。
3. **混合评估器**：数字、公式、证据和集合匹配由程序完成；解释质量、过度推断和安全边界由 Hy3 Judge 评审。
4. **阴性对照**：在未触发目标八类异常的窗口中，检查模型是否因“被要求找问题”而虚构信号。
5. **评估器消融**：比较纯 Judge、纯规则和混合评估器与人工标注的一致性，验证评估方法本身，而不只验证应用。

## 二、目标用户与场景必要性

### 2.1 目标用户

- 财经专业学生和财务分析学习者；
- 投研、财务分析或审计岗位的实习生；
- 需要进行基本面初筛的个人研究者；
- 需要从大量公司中定位重点核查对象的辅助分析人员。

### 2.2 当前工作方式的不足

人工翻阅多年财务报表耗时较长，且容易遗漏跨期变化。Wind、Choice 等工具能够展示指标和阈值，但通常不会解释不同指标之间的组合关系，也难以明确区分事实、可能原因和结论边界。

本项目不替代专业审计或投资分析，而是提供一个可复核的初筛流程：

~~~text
结构化财务数据
      ↓
Hy3 盲扫异常信号
      ↓
异常卡片：事实—公式—推断—替代解释—核查建议
      ↓
混合评估器复算与检查
      ↓
人工决定是否进一步调查
~~~

### 2.3 为什么使用 Hy3

规则引擎适合判断预设条件是否触发，但无法穷举所有复合关系，也无法稳定完成解释、排序、替代原因生成和结论边界控制。Hy3 在本项目中承担：

- 对八类目标异常进行直接识别和综合判断；
- 对跨指标关系进行自然语言解释；
- 将未经证实的原因明确标注为待核查假设；
- 生成针对性的下一步核查建议；
- 对异常的重要程度进行开放式排序；
- 在加分模块中判断管理层叙事与数据是否一致。

规则引擎只存在于评估侧，不向默认应用链路提供候选异常。

## 三、范围与任务定义

### 3.1 范围约束

为控制两周初稿工期，第一版严格限定：

- 只分析制造业上市公司；
- 使用连续 3～5 年结构化 CSV/Excel 数据；
- 不把 PDF 表格解析作为核心任务；
- 固定八类目标异常，并保留一个 other 类；
- 重点完成四类异常的可控注入实验；
- 不预测股价；
- 不提供买卖建议；
- 不判断公司存在财务造假；
- 不覆盖银行、保险、证券和房地产等报表结构差异较大的行业。

制造业样本可来自机械设备、电子制造、化工、汽车零部件、医药制造和食品制造等子行业。

### 3.2 输入

一个公司窗口样本由以下内容组成：

- 一家制造业上市公司；
- 连续 3～5 个会计年度；
- 利润表、资产负债表和现金流量表的核心科目；
- 数据来源清单和稳定字段标识；
- 可选的管理层讨论与分析节选。

核心字段包括：

- 利润表：营业收入、营业成本、毛利、销售费用、管理费用、研发费用、营业利润、利润总额、净利润、非经常性损益；
- 资产负债表：货币资金、应收账款、存货、商誉、流动资产、流动负债、短期借款、总资产、总负债、所有者权益、未分配利润；
- 现金流量表：经营活动、投资活动和筹资活动现金流量净额、期初及期末现金余额；
- 元数据：公司、年度、行业、币种、单位、报表口径、原始来源 URL 和提取时间。

### 3.3 八类目标异常

以下阈值为方案阶段的初始定义，开发阶段将在 2 家公司上试跑后冻结，测试集运行期间不得再修改。

| signal_type | 中文名称 | 初始触发条件 |
|---|---|---|
| cashflow_profit_divergence | 经营现金流与净利润背离 | 经营现金流/净利润连续两年低于 0.5，且净利润为正 |
| receivables_revenue_divergence | 应收账款与营收背离 | 应收账款增速减营业收入增速不低于 20 个百分点 |
| inventory_cost_divergence | 存货与营业成本背离 | 存货增速减营业成本增速不低于 20 个百分点 |
| gross_net_margin_divergence | 毛利率与净利率背离 | 毛利率上升而净利率下降幅度不低于 2 个百分点 |
| nonrecurring_profit_dependence | 非经常性损益依赖 | 非经常性损益绝对值占净利润比例不低于 30% |
| goodwill_net_assets_pressure | 商誉占净资产压力 | 商誉占所有者权益比例不低于 20% |
| short_term_solvency_pressure | 短期偿债压力 | 流动比率低于 1，且短期借款/货币资金高于 1 |
| impairment_loss_surge | 减值损失激增 | 减值损失同比增幅不低于 100%，且占利润总额绝对值不低于 10% |

对于分母为零、负数、数据缺失、会计政策变更或前期数据重述等情况，规则返回 not_applicable 或 requires_review，不强行判定。

### 3.4 other 类

Hy3 可以输出枚举外的合理异常：

- other 不进入八类目标异常的主召回率和精确率；
- 由人工判断是否为合理额外发现；
- 合理 other 单独报告；
- 无依据 other 计入无依据结论率；
- 不把合理的枚举外发现自动视为误报。

### 3.5 输出契约

Hy3 输出严格 JSON。每张异常卡片包含：

~~~json
{
  "signal_type": "receivables_revenue_divergence",
  "signal_name": "应收账款增速显著超过营业收入增速",
  "severity": "high",
  "periods": ["2023", "2024"],
  "fact_basis": [
    {
      "fact_id": "fact_001",
      "metric_key": "accounts_receivable",
      "metric_name": "应收账款",
      "period": "2024",
      "value": 850000000,
      "unit": "CNY",
      "source_record_id": "company001_bs_accounts_receivable_2024",
      "source_file": "company001_financials.csv",
      "source_row": 18,
      "source_column": "2024",
      "statement": "balance_sheet"
    }
  ],
  "calculation": {
    "formula_id": "receivables_growth_minus_revenue_growth",
    "operand_fact_ids": ["fact_001", "fact_002", "fact_003", "fact_004"],
    "reported_result": 0.361,
    "readable": "应收账款同比增长48.1%，营业收入同比增长12.0%，差额36.1个百分点"
  },
  "supported_explanation": null,
  "possible_explanations": [
    "期末销售集中",
    "信用政策变化",
    "部分客户回款周期延长"
  ],
  "next_checks": [
    "检查应收账款账龄结构",
    "核查前五大应收对象及期后回款"
  ],
  "conclusion_boundary": "当前结构化数据只能证明该指标关系值得核查，不能确定具体原因，也不能据此认定财务造假。"
}
~~~

source_record_id 是稳定主键，行号和列名用于 Demo 展示。即使 CSV 排序发生变化，评估器仍优先通过稳定主键回表。

### 4.1 总体架构

│          └── 阴性对照生成                            │
└───────────────────────┬─────────────────────────────┘

          ▼                            ▼
┌───────────────────────┐    ┌─────────────────────────┐
│ 应用侧                 │    │ 评估侧                  │
│ 指标预计算             │    │ 规则 Oracle             │
│ Prompt + JSON Schema   │    │ · 原始数值回表          │
│ Hy3 直接识别           │───►│ · 公式与算术复算        │
│ 解析与格式重试         │    │ · 证据定位检查          │

                             │ · 排序与重要性           │

                             └────────────┬────────────┘
                                          ▼
                                维度结果、错误归因与报告
~~~

### 4.2 关键架构决策

#### 决策一：主链路不接收规则候选

默认应用流程为“结构化数据 → Hy3 直接识别”。规则只在输出产生后执行，用作评估侧 Oracle。如果把候选答案提前提供给 Hy3，模型的漏报率将失去测量意义。

#### 决策二：金标准分层

真实样本：

~~~text
规则触发结果 + 双人独立标注 + 必要的公开材料复核
                     ↓
                参考异常集合
~~~

注入样本：

~~~text
注入操作元数据
  · 注入类型
  · 起始期间
  · 修改字段
  · 注入强度
  · 预期目标异常
                     ↓
                 独立真值
~~~

注入元数据独立于模型输出和评估执行过程。它仍然受预定义八类异常体系约束，因此本项目不会宣称能够测量枚举外全部财务风险。

#### 决策三：应用配置与实验对象保持一致

Streamlit Demo 默认展示 Hy3 直接识别模式。规则辅助＋Hy3 仅作为实验对比臂，不替代默认产品配置，避免“实际产品和主要评测对象不一致”。

## 五、重点技术

### 5.1 结构化输出与格式自修复

采用三层约束：

1. Prompt 中提供完整 JSON Schema、八类枚举和少量示例；
2. 使用 Schema 校验输出，格式失败时将错误原因回传 Hy3，最多重试 2 次；
3. 格式通过后执行回表和公式校验，但校验失败不触发内容重试，避免评估器帮助模型修正事实错误。

格式重试只修复 JSON 结构，不允许改写异常分析内容。

### 5.2 安全公式注册表

不直接执行模型生成的表达式，避免任意代码执行风险。每类异常在 formula_registry.yaml 中定义允许的公式、科目、期间关系和异常方向。

评估器依次检查：

1. formula_id 是否适用于 signal_type；
2. operand_fact_ids 是否引用了正确科目和期间；
3. 原始输入值是否与数据源一致；
4. 使用注册表中的安全函数重新计算；
5. reported_result 与复算结果是否在容差内。

这样可以同时发现：

- 原始数字错误；
- 年份引用错误；
- 分子、分母或期间选择错误；
- 算术结果错误；
- 公式与异常类型不匹配。

### 5.3 数据来源与单元格级证据

每个基底公司建立 data_manifest.csv，至少记录：

- 公司名称和证券代码；
- 年报年度；
- 原始公开来源 URL；
- 下载或提取日期；
- 报表口径和单位；
- 提取者；
- 数据字段与原始报表科目的映射。

每条数据使用 source_record_id 作为稳定定位，同时保存源文件、行号和列名，支持评估器自动回表以及 Demo 可视化。

### 5.4 会计一致的注入引擎

初稿阶段重点实现四类可控注入：

- 应收账款与营收背离；
- 存货与营业成本背离；
- 商誉占净资产压力；
- 毛利率与净利率背离。

示例一：模拟回款延迟。

~~~text
应收账款 += Δ
货币资金 -= Δ
经营活动现金流量净额 -= Δ
利润不变
~~~

示例二：模拟现金收购形成商誉。

~~~text
商誉 += Δ
货币资金 -= Δ
投资活动现金流量净额 -= Δ
利润不变
~~~

每次注入后必须执行：

\[
\text{总资产}=\text{总负债}+\text{所有者权益}
\]

\[
\text{期末现金}-\text{期初现金}
=\text{CFO}+\text{CFI}+\text{CFF}
\]

\[
\text{毛利}=\text{营业收入}-\text{营业成本}
\]

并重新运行八类规则：

- 仅触发目标异常：标记为单异常样本；
- 同时触发其他异常：记录为复合异常样本，并将全部触发项写入真值；
- 产生无法解释的附带异常或恒等式失败：样本作废。

### 5.5 严重度的可复现定义

不同异常的恶化方向不一致，因此不使用统一的 x/θ 倍数。对每种异常预先定义：

- 触发阈值 θ；
- 风险方向 d：越大越危险取 1，越小越危险取 -1；
- 严重度尺度 σ。

定义标准化超阈值程度：

\[
s=\frac{d(x-\theta)}{\sigma}
\]

| s | 标签 |
|---|---|
| s < 0 | 阈下阴性样本 |
| 0 ≤ s < 0.5 | low |
| 0.5 ≤ s < 1.5 | medium |
| s ≥ 1.5 | high |

阈值和尺度只在开发集上调整，测试集运行前冻结。

### 5.6 Hy3 Judge 的使用约束

- 纯 Judge 基线只接收模型报告和 rubric，不接收规则结果；
- 混合评估器中的 Judge 接收规则校验结果，避免被流畅文案掩盖的事实错误欺骗；
- 评审时隐藏输出来源和实验臂；
- 使用固定 Prompt 和固定参数；
- 一致性子集重复评估 3 次，记录均值、中位数和标准差；
- 在局限性中说明生成模型与 Judge 同属 Hy3 可能带来的自评偏差。

## 六、评估方法

### 6.1 评估维度

| 编号 | 维度 | 可操作判定动作 | 方法 | 输出 |
|---|---|---|---|---|
| D1 | 原始数值准确性 | 仅检查 fact_basis 中声称来自报表的数值；单位归一化后按 source_record_id 回表，相对误差不超过 1% 视为命中 | 规则 | 命中率 |
| D2 | 公式与计算正确性 | 检查 formula_id、科目、期间、分子分母和算术结果；使用安全公式注册表复算 | 规则 | 公式正确率、算术通过率 |
| D3 | 证据可追溯性 | 检查 source_record_id、源文件、报表归属、期间和字段是否有效 | 规则 | 可追溯率 |
| D4 | 覆盖完整性 | 输出的八类 signal_type 与金标准集合匹配，计算普通召回、加权召回和严重异常漏报率 | 规则 | R、Rw、MRhigh |
| D5 | 误报控制 | 对枚举内但不在金标准中的输出进行规则复核和人工确认；不成立者计为 FP | 混合 | 精确率、误报率 |
| D6 | 重要性排序 | 比较模型 severity 与金标准等级；有序标签使用加权 Kappa，排序使用 Spearman | 混合 | 等级一致性 |
| D7 | 解释与结论边界 | 按锚点 rubric 检查事实和推测是否分离、替代解释是否明确为假设、核查建议是否可执行、是否存在无依据确定归因 | Hy3 Judge | 1～5 分、错误标签 |
| D8 | 安全合规 | 规则先检测买卖建议、目标价、造假认定等显式表述，Judge 再检查隐含指控和越界推断 | 混合 | 违规率 |

### 6.2 D7 锚点式 Rubric

| 分数 | 明确标准 |
|---|---|
| 5 | 事实、支持性解释和可能原因严格分开；无依据原因均标为假设；包含针对当前信号的核查建议和清晰结论边界 |
| 4 | 不存在事实性越界；替代解释和核查建议基本完整，但有一项不够具体 |
| 3 | 核心解释合理，但事实与推测标识不够稳定，或核查建议较泛化 |
| 2 | 存在一处重要的无依据归因，或没有说明替代解释和结论边界 |
| 1 | 将异常信号直接认定为造假、经营失败或投资结论，或解释与数据无关 |

### 6.3 核心指标

设金标准目标异常集合为 G，模型输出的枚举内异常集合为 O：

\[
TP=|O\cap G|
\]

\[
P=\frac{TP}{TP+FP}
\]

\[
R=\frac{TP}{|G|}
\]

\[
F_1=\frac{2PR}{P+R}
\]

令金标准异常 i 的严重程度权重为 \(w_i\)，high、medium、low 分别取 3、2、1：

\[
R_w=
\frac{\sum_{i\in O\cap G}w_i}
{\sum_{i\in G}w_i}
\]

严重异常漏报率为：

\[
\mathrm{MR}_{high}
=
\frac{|G_{high}\setminus O|}
{|G_{high}|}
\]

如果某个分组内不存在 high 异常，则该分组的 MRhigh 记为 N/A，不记为 0。

### 6.4 指标层级

主指标：

- 严重异常漏报率 MRhigh。

五个支撑指标：

- 严重度加权召回率 Rw；
- 异常识别精确率 P；
- 原始数值准确率；
- 公式与算术复算通过率；
- 过度推断率。

F1、普通召回率、证据可追溯率、合规违规率、合理 other 数量和分类型结果放在附录。

所有百分比同时报告分子和分母，例如“18.2%（4/22）”。

## 七、评估方法有效性验证

### 7.1 实验一：应用能力对比

| 实验臂 | 配置 | 定位 |
|---|---|---|
| A1 | Hy3 直接分析结构化数据 | 默认产品和主要评测对象 |
| A2 | 纯规则扫描 | 八类预定义信号的确定性上界，不具备完整解释能力 |
| A3 | 规则候选＋Hy3 确认、驳回和补充 | 工程增强对比臂 |

输出：

| 实验臂 | MRhigh ↓ | Rw ↑ | P ↑ | 过度推断率 ↓ | D7 解释分 ↑ |
|---|---:|---:|---:|---:|---:|
| A1 Hy3 直接 | | | | | |
| A2 纯规则上界 | | | | N/A | N/A |
| A3 规则＋Hy3 | | | | | |

A2 在注入样本上可能接近满分，因此不将其包装成与 Hy3 完全等价的应用，而是作为目标八类信号的规则上界。

### 7.2 实验二：注入强度梯度

在四类重点注入异常上设置多个标准化强度 s，观察模型漏报率随强度变化的曲线。

| 异常类型 | s | 样本数 | MRhigh | Rw | P |
|---|---:|---:|---:|---:|---:|
| 应收账款与营收背离 | | | | | |
| 存货与营业成本背离 | | | | | |
| 商誉占净资产压力 | | | | | |
| 毛利率与净利率背离 | | | | | |

目标是识别 Hy3 在不同异常类型上的敏感度临界区间，而不是预设模型一定达到某个准确率。

### 7.3 实验三：阴性对照

阴性对照只表示“未触发目标八类异常”，不表示公司财务绝对健康。

包括：

- 距离触发阈值较远的窗口；
- 刚低于阈值的边界窗口；
- 具有正常年度波动、但不满足规则的窗口。

输出：

| 对照类型 | 窗口数 | 模型报告目标异常数 | 经人工确认的 FP | 合理 other | 误报率 |
|---|---:|---:|---:|---:|---:|
| 明显阴性 | | | | | |
| 阈下边界 | | | | | |

### 7.4 实验四：好、中、差判别力

围绕相同输入构造三档输出：

- 好：人工修正全部事实和计算错误，解释与结论边界完整；
- 中：Hy3 原始输出；
- 差：程序化加入数字、年份、公式、证据或过度推断错误。

指标：

- 三档完整排序准确率；
- 两两排序准确率；
- Kendall’s τ；
- 不同评估器对错误类型的识别率。

### 7.5 实验五：对抗性与评估器消融

对抗输出包括：

| 攻击类型 | 构造方式 |
|---|---|
| 篇幅膨胀 | 不增加事实内容，只将文字扩写到约三倍 |
| 术语堆砌 | 添加专业术语，但不提供相应数字和逻辑 |
| 伪造证据 | 修改 source_record_id、年份、行列或数值 |
| 错误公式 | 使用错误期间、分母或异常类型不匹配的公式 |
| 幻觉精确数字 | 生成输入中不存在的高精度数字 |
| 重复计数 | 将同一根因包装成多张异常卡片 |
| 过度推断 | 把关注信号直接表述为造假或买卖结论 |

三种评估器在共同错误检测任务上比较：

| 评估器 | 错误检测 P | 错误检测 R | 错误检测 F1 | 与人工总分 Spearman ρ | 三档排序准确率 |
|---|---:|---:|---:|---:|---:|
| 纯 Hy3 Judge | | | | | |
| 纯规则 | | | | | |
| 混合评估器 | | | | | |

另外按攻击类型报告识别率，避免比较不同量纲的“平均分”。

### 7.6 实验六：人工一致性和 Judge 稳定性

标注安排：

- 本人和 1 名同学共同参与；
- 独立标注 50～60 张异常卡片；
- 标注前使用 8～10 张练习卡片校准 rubric；
- 正式标注时不讨论；
- 一致性指标必须在分歧协商前计算；
- 分歧协商后的标签仅用于形成最终参考集。

指标：

- 二元或名义标签：Cohen’s κ 和原始一致率；
- 有序等级：加权 Cohen’s κ；
- 连续总分或排序：Spearman ρ；
- 自动评估器与人工共识标签的相关性；
- Judge 在 20～30 张一致性子集上重复 3 次的均值、中位数和标准差。

## 八、评测样本设计

### 8.1 两类数据对象

为避免把“公司窗口”和“对抗报告”混为同一种样本，数据分为：

1. **应用评测窗口**：用于测试 Hy3 是否能够发现异常；
2. **评估器验证输出**：基于应用窗口生成的正常、三档和对抗报告，用于验证评估器。

### 8.2 应用评测窗口

| 类型 | 计划数量 | 说明 |
|---|---:|---|
| 真实公司窗口 | 8 | 每家公司连续 3～5 年 |
| 重点异常注入窗口 | 20～24 | 四类异常、多档强度、允许少量复合样本 |
| 阴性对照窗口 | 8 | 明显阴性和阈下边界 |
| 合计 | 36～40 | 同时报告公司数和窗口数 |

其他四类异常主要通过真实样本和规则验证覆盖；如果工期允许，再扩展其注入模板。

### 8.3 评估器验证输出

- 从应用窗口获得 Hy3 原始输出；
- 为部分输出制作人工修正版；
- 为部分输出制作程序化劣化版；
- 构造约 40 条对抗输出；
- 选择 50～60 张代表性卡片进行双人标注。

### 8.4 数据划分与统计独立性

- 以基础公司为单位划分开发集和测试集；
- 同一家公司的真实及全部派生窗口只能进入同一个集合；
- 阈值、严重度尺度和 Prompt 只在开发集调整；
- 测试集运行后不再修改规则；
- 同时报告 8 家基础公司和 36～40 个窗口，不能把派生窗口宣称为完全独立公司样本；
- 置信区间采用按基础公司聚类的 bootstrap；
- 由于基础公司数量较少，结果以探索性实验为主，不外推到全部制造业上市公司。

### 8.5 难度分层

| 难度 | 定义 |
|---|---|
| 简单 | 强度显著超过阈值，且单一信号明显 |
| 中等 | 强度中等，或需要比较多个年度 |
| 困难 | 接近阈值、存在基数效应、缺失值或合理替代解释 |
| 复合 | 同一窗口同时触发两个以上目标异常 |
| 对抗 | 输出中的数字、公式、证据或语言被刻意扰动 |

## 十、风险与能力边界

### 10.1 风险与应对

| 风险 | 影响 | 应对与降级 |
|---|---|---|
| 手工数据整理超时 | 挤压实验时间 | 基底公司固定为 8 家，不做 PDF 自动解析 |
| 八类注入全部实现困难 | 三表一致性难维护 | 初稿只承诺四类完整注入，其他类型使用真实窗口 |
| 注入产生附带异常 | 污染标准答案 | 注入后运行全部规则，标记复合样本或作废 |
| Hy3 JSON 不稳定 | 自动流程中断 | Schema 校验和最多两次格式修复 |
| Hy3 调用额度不足 | Judge 重复实验不完整 | 缓存所有原始输出；重复评估只在子集执行；实际额度以活动平台为准 |
| 双人标注来不及 | 一致性实验不足 | 优先标注 50 张代表性卡片，不追求全量 |
| Streamlit 延误 | 初稿无法展示 | CLI、JSONL 和评估脚本优先，Streamlit 最后开发 |

### 10.2 能力边界

1. 主指标只覆盖预定义八类异常，不能代表模型发现任意财务风险的完整能力。
2. 注入样本即使满足报表恒等式，也无法完全模拟真实经营活动或真实财务舞弊痕迹。
3. 结构化数据可以支持异常识别，但通常不足以证明异常产生的具体原因，因此可能原因必须作为假设表达。
4. 八家基础公司样本量有限，实验结论只用于项目验证，不外推到全部上市公司。
5. Hy3 同时参与生成和语义评审，可能存在自评偏差；本项目通过规则校验、匿名评审和人工标注降低但不能完全消除该偏差。
6. 系统只能提供辅助初筛，不替代注册会计师、审计机构或专业投资分析。

## 十二、加分模块

### 12.1 管理层叙事一致性

对少量样本加入管理层讨论文本，判断表述属于：

- 数据支持；
- 部分支持；
- 证据不足；
- 与数据矛盾。

示例：

~~~text
管理层表述：
“公司经营质量和回款能力持续改善。”

数据：
营业收入 +12%
应收账款 +47%
经营现金流 -31%

输出：
判定：部分支持或与数据矛盾
依据：收入增长，但回款相关指标未支持“持续改善”
边界：不能仅据此认定管理层故意误导
~~~

该模块只用于 Demo 和典型案例，不承担主数据集和主指标压力。

### 12.2 真实后验案例

如果时间允许，选择少量后来出现商誉减值、监管问询或经营风险的公司，回看事件发生前 1～2 年是否已存在目标信号。该实验只作为案例研究，不作为预测准确率，也不据此宣称系统能够预测“暴雷”。
