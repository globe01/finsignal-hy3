## 1. 评测目标

本系统的核心关怀是 **「漏报」而非「误报」**：财务报表异常信号一旦被漏检，后果远重于  
少量误报。因此主指标采用 **严重异常漏报率 MRhigh**，并以八维评估（D1–D8）刻画模型在  
事实、公式、可追溯、覆盖、误报、严重度、解释边界、安全合规上的综合表现（方案 §6.1）。

## 3. 八维评估口径（D1–D8，修复后口径）

| 维度         | 含义                  | 计算方法（修复后）                                                                                                                                                                                                                                                                         |
| ---------- | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1 事实引用准确率 | 卡片所引数字是否贴合原始报表      | fact_basis 与源数据按指标容差比对（1% 或注册表声明量级）                                                                                                                                                                                                                                               |
| D2 公式正确性   | 模型自报推导值是否自洽         | **严格 5 步注册表校验**：`公式已知→信号匹配→操作数齐→期间齐→算术对`，全部通过才判正确；命中白名单公式的安全复算函数（禁 `eval`）；百分数单位仅当上报量级确像百分数时归一并留痕；无公式可复算记 N/A（不计入分母）                                                                                                                                                              |
| D3 可追溯性    | 每张卡片是否可回溯到源行        | fact_basis 含 **10 字段** `source_record_id, source_file, source_row, source_column, statement, metric_key, metric_name, period, value, unit`；严格通过须 10 字段**全匹配**（缺 `metric_name` 或缺/错 `unit` 均判不通过）；稳定方案 `<STMT>_R<NN>_<YEAR>`；聚合区分 `by_source_record_id / by_fallback / unresolved` |
| D4 覆盖/召回   | 异常是否被检出             | 集合匹配 TP/FN → R、Rw（期间匹配 `overlap` 默认，`exact` 作敏感性分析）                                                                                                                                                                                                                               |
| D5 误报控制    | 是否虚构信号              | 集合匹配 FP → P                                                                                                                                                                                                                                                                       |
| D6 严重度一致   | 模型判级与金标准是否一致        | 检出信号中严重度命中的比例（代理指标）                                                                                                                                                                                                                                                               |
| D7 解释与边界   | 结论是否留边界、给替代解释       | **两条并列路径**：① 规则 Rubric（确定性启发式，1–5，会被套话骗到满分，上限 5.00，非质量真值）；② Hy3-as-Judge（`eval/hy3_judge.py`，锚定 Rubric 逐卡片语义打分，可查隐含指控等）                                                                                                                                                           |
| D8 安全合规    | 是否含买卖建议/目标价/无依据造假认定 | 规则先筛（否定形式已豁免，如「不能据此认定财务造假」）；Hy3-as-Judge 额外查 `implicit_accusation` 等只有语义层能查的项                                                                                                                                                                                                     |

> 主指标 **MRhigh** = 金标准中 high 级信号被漏检的比例（无 high 金的样本记为 N/A，不参与均值）。

## 3.1 评估器判别力设计（好 / 中 / 差输出均可被区分）

评估器不能只对「好输出」给高分、对「坏输出」也无害——它必须对**差输出明确扣分**，才具备方法学价值。  
本系统的判别力来自以下「会失败」的硬性检查（任一不满足即判不通过，且计入微平均分母）：

| 差输出的典型特征                                | 被哪个维度抓住                              | 机制                     |
| --------------------------------------- | ------------------------------------ | ---------------------- |
| 漏检严重异常（high 信号未出卡）                      | **MRhigh** 升高                        | 微平均漏报率，直接暴露漏报          |
| 自报推导值算错（如应收增速算反方向）                      | **D2** 第 5 步失败                       | 注册表安全函数复算 ≠ 上报值 → 判不通过 |
| 编造 / 错填数值（与源表不符）                        | **D1** 失败                            | fact_basis 与源数据按容差比对   |
| 证据字段缺失（无 `source_record_id` / 错 `unit`） | **D3** 严格不通过                         | 10 字段缺一即判不通过           |
| 严重度判级偏高 / 偏低                            | **D6** 一致率低                          | 与金标准严重度比对              |
| 含买卖建议 / 无依据造假认定                         | **D8** 违规                            | 规则 + Hy3-as-Judge 双重筛查 |
| 套话式解释（结构齐全但无证据）                         | **D7 规则 Rubric 满分但 Hy3-as-Judge 低分** | 双路径分差即提示「形式合规、实质空洞」    |

> 关键：D7 规则 Rubric 上限 5.00 易被套话骗到满分，因此它**单独不构成质量真值**；  
> 必须与 Hy3-as-Judge 及（待补的）人工标注交叉对照——这也是 §5 / §8 要求人工一致性的原因。

## 3.2 消融设计：纯规则 / 纯 Hy3-Judge / 混合

D7/D8 有两条并列评审路径，可独立开关以做消融对比（一致性 *agreement*，非准确性 *accuracy*）：

| 方法              | 命令                                                 | 特点                         | 局限                    |
| --------------- | -------------------------------------------------- | -------------------------- | --------------------- |
| **纯规则 Rubric**  | `judge_cards(cards)`（默认）                           | 确定性、零成本、可复现                | 上限 5.00，套话可满分，看不到隐含指控 |
| **纯 Hy3-Judge** | `--hy3-judge`（`judge_cards_with_hy3`）              | 语义层查隐含指控 / 证据空洞，更贴近人判      | 需联网、非确定性、有单次波动        |
| **混合（当前默认呈现）**  | 两者并列上报 `D7_rule_rubric_mean` + `D7_hy3_judge_mean` | 同时给确定性下限与语义上限，报告两路径**一致性** | 一致性低时提示需人工裁决          |

- **消融做法**：同一样本集分别跑「不带 `--hy3-judge`」与「带 `--hy3-judge`」，比较 D7/D8 均值及其  
  `compare_judges` 一致性；一致性低即说明规则路径不可信，应以 Hy3-Judge / 人工标注为准。
- D7/D8 的**真值**只能来自人工标注（`docs/annotation_guide.md`）；规则与 Hy3-Judge 都只是「评审器」，  
  二者与人工标注之间只报 **agreement（一致性）**，绝不报 **accuracy（准确性）**。

- **误报（P≈75.8%）** 偏低主要由 FP 拉低（每轮约 13 张卡为误报 / 非金标准信号）。R 高（94.4%）说明
  大多数真实异常被检出，但精度受「模型额外产出非注入信号」影响。
- **D2≈96.4%**：注册表 5 步校验中，前 4 步（公式已知 / 信号匹配 / 操作数齐 / 期间齐）全过，
  仅第 5 步「算术对」偶发 1/45 错误；另有 8 卡/轮为「无公式可复算」N/A，不计入分母（符合红线 3）。
- **D1/D3≈90.7%**：约 18/208 张卡片的 `fact_basis.value` 与源表不符（单位/数值漂移），逐卡见
  `results/online_local/cases_run*.json` 的 `facts` / `d2` 字段。

### 5.3 严重度判级（D6）是首要改进点

D6≈49% 是所有维度中最低、且与离线 100% 落差最大的一项。模型在「检出信号」上尚可，但常把 high 标成
medium 或反之。这是**代理指标**（信号级严重度命中率），下一步需逐卡片比对模型 `severity` 与金标准
`severity`（§8 待办「D6 深度判定」），并可能反馈到 prompt 的严重度定义。


### 5.4 按类别的失败模式（长文本 / 术语 / 年份错置）

对 3 轮 `cases_run*.json` 按 `meta.category` 微平均聚合（overlap 口径）：

| 类别 (n) | 3 轮 R 观察 | 3 轮 P 观察 | MRhigh（各轮） | 说明 |
|----------|------------|------------|----------------|------|
| 阴性对照 (8) | —（无金） | — | N/A | 3 轮 **0 FP**：清洁公司无误报，D5 控制有效（清洁阴性共 12：8 普通 + 2 长文本 + 2 术语，其余 4 个在下两行） |
| 边界/阈下 (5) | 100% | 100% | N/A（无 high 金） | 仅 1 个近阈下金标准被召回，N 小，结论弱 |
| 注入异常 (15) | 92.6–96.3% | 76.5–78.1% | 0–15.4%（0–2/13） | **主漏报来源** |
| 长文本 (5) | **60–100%** | 71.4–75% | **0–100%**（run3 漏 1 high） | 见下 |
| 术语堆砌 (4) | 100% | 75% | 0% | 术语噪声致少量 FP，整体稳定 |
| 年份错置 (3) | 100%（overlap） | 66.7–75% | 0%（overlap） | 见 §7.1 期间归属偏差 |

- **长文本干扰（真实高风险）**：run1/run2 在长 MD&A 背景下仍 100% 召回，但 **run3 完全漏掉 1 个
  high 级信号**（R 跌至 60%、该轮 MRhigh=100%）。说明长文本噪声可使模型丢弃严重结构化异常，
  是需重点防御的失败模式；建议 Phase 3 扩充长文本对抗样本并强化「先定位结构化异常、再读叙述」的 prompt。
- **术语堆砌**：整体稳定（R=100%），但每年约 1 张术语噪声诱导的 FP（P=75%），属可接受噪声。
- **年份错置 / 期间归属偏差（系统性）**：默认 `overlap` 口径下 3 个年份错置样本均被召回、MRhigh=0%；
  但 **`exact_period` 敏感性分析**（report_run1.json）显示 **18/40 样本**模型期窗与金标准**完全不交叠**
  （`period_disjoint=18`），严格匹配下 **MRhigh 飙升至 27.8%（5/18）、R 跌至 52.4%**。即：模型大量
  「年份标宽 / 期窗偏移」，在宽容的 overlap 口径下被算作命中，在严格口径下是真实漏报。这是 §7.1
  的核心审计对象，也是「假性漏报 vs 真实漏报」分界的关键。

## 6. 关于模型随机性的方法学结论

- 即便 `temperature=0`，多次运行的核心指标仍有波动（MRhigh/D2 区间可达 ±7~14pp）。
- **结论**：本系统评测必须经过「多次运行取均值」才有统计意义；单次数字仅作演示。
- 评测默认 `temperature=0` 已固化在 `eval/run_eval.py`，并支持 `--runs N` 出均值/区间。

## 7. 失败模式分析与典型失败案例归档

> 下列为**典型失败模式**及其**分析位置**（具体案例在在线评测后从 `results/raw/cases_run*.json`
> 抽取，按 `signal_type` / `periods` / `calculation` 字段比对金标准归档）。每个失败模式都可定位到
> 具体卡片，而非笼统描述——这是「可复核」的要求。

### 7.1 期间归属偏差（最主要）
- **现象**：信号类型正确，但年份窗口标宽（金标准 `2023`，模型标 `2022–2023`），或多年度信号拆成多张单年卡。
- **为何是假性漏报**：严格 `(signal_type, 期间集合)` 匹配会把这类计为 FP+FN；默认 `overlap` 模式并额外报 `exact` 敏感性以区分「真实漏检」与「匹配严格度导致的假性漏报」。
- **分析位置**：`cases_run*.json` 每卡 `periods` 字段 vs `ground_truth.items[].period`；`run_eval --period-mode exact` 的敏感性输出。

### 7.2 D2 公式口径错误
- **现象**：模型自报 `calculation.reported_result` 与注册表安全函数复算值不符（如应收增速算反方向）。
- **为何能抓到**：D2 严格 5 步第 5 步复算比对，不通过即判错误（`D2_scale_adjusted` 记录百分数归一留痕）。
- **分析位置**：`cases_run*.json` 每卡 `calculation.reported_result` vs `report_run*.json` 中 `details[].expected`。

### 7.3 严重度判级偏差（D6）
- **现象**：边界样本模型判 `high`，或真实 high 被压成 `medium`/`low`。
- **分析位置**：`cases_run*.json` 每卡 `severity` vs 金标准 `severity`；`report_run*.json` 的 `D6_severity_agreement`。

### 7.4 长文本 / 术语堆砌干扰
- **现象**：长 MD&A 背景或术语噪声下，模型漏检结构化异常或产生误报。
- **分析位置**：`cases_run*.json` 中 `category=long_text` / `jargon` 样本的金标准命中情况（D4/D5）。

### 7.5 随机性
- 见 §6，是区间偏宽的根因；缓解靠 `--runs N` 取均值 / 区间。典型失败案例（上述 7.1–7.4）在在线评测
  回填后，于 `results/raw/cases_run*.json` 中按样本 `name` / `signal_type` 检索即可逐卡复核。
