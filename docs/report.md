**三个方法学红线（本报告所有数字都遵守）：**
1. **金标准独立于规则引擎**：注入样本的金标准来自注入元数据（`InjectionMeta`），规则层只用于「注入是否真的生效」的有效性核验，**不作金标准来源**（方案 §4.2 四层真值）。
2. **D2 严格 5 步注册表校验，禁 `eval()`、禁「多候选命中任一」**：必须 `公式已知→信号匹配→操作数齐→期间齐→算术对` 五步全过才判正确（方案 §5.2）。
3. **主指标一律微平均并报告分子/分母**，无 high 金的样本记 N/A（不记 0），macro 仅作附加参考（方案 §6.3）。
4. **离线自检与在线评测必须分开展示**：`results/` 中入库的 7 个文件是**评估器自检**（确定性「完美模型」），不是 Hy3 性能；Hy3 在线性能须单独运行、单独成节、且不可并入自检结果。

## 1. 评测目标

本系统的核心关怀是 **「漏报」而非「误报」**：财务报表异常信号一旦被漏检，后果远重于
少量误报。因此主指标采用 **严重异常漏报率 MRhigh**，并以八维评估（D1–D8）刻画模型在
事实、公式、可追溯、覆盖、误报、严重度、解释边界、安全合规上的综合表现（方案 §6.1）。

## 2. 数据集构造（40 个合成样本，方案 §5.4 / §7.3 / §8.2）

> 全部为**合成（synthetic）**数据，由清洁基底 + 受控异常注入生成，**不冒充任何真实上市公司**，
> 不构成任何公司存在财务造假的暗示。数据由 `eval/run_eval.py::build_dataset()` 程序化、确定性生成。

| 类别 | 数量 | 说明 |
|------|------|------|
| 阴性对照（清洁公司） | 10 | 8 普通阴性 + 2 长文本阴性 + 2 术语堆砌阴性；金标准为空，验证 D5 误报控制 |
| 注入异常（5 类 × 低/中/高三档） | 15 | `receivables/inventory/goodwill/gross_net/cashflow` 各 3 档强度，会计恒等式自洽 |
| 边界/阈下对照 | 5 | 5 类各近阈下（强度 ×0.5），验证稳定性与阈下设计 |
| 长文本对抗（带 MD&A 背景，不涉数值） | 5 | 2 阴性 + 3 注入；测试长文本干扰下是否仍能定位结构化异常 |
| 术语堆砌对抗 | 4 | 2 阴性 + 2 注入；测试术语噪声是否导致误报/漏报 |
| 年份错置（数字对、期间错） | 3 | 不同日历年份锚点的应收注入窗口，检验期间归属 |

- 注入信号类型：`receivables_revenue_divergence`、`inventory_cost_divergence`、
  `goodwill_net_assets_pressure`、`gross_net_margin_divergence`、`cashflow_profit_divergence`。
- **复合样本说明**：应收/存货/毛利-净利类注入会同时压低经营性现金流，故金标准中除目标信号外还记录
  `cashflow_profit_divergence`（方案 §5.4「记录全部触发项」）。该复合项由注入元数据直接给出，
  与模型输出解耦，不依赖规则 Oracle 复算。
- **金标准来源（关键修正）**：注入样本的金标准**来自注入元数据**（`generator/inject.py` 的 `InjectionMeta`），
  规则引擎（`eval/rules.py`）仅用于「注入是否真的触发了目标信号」的有效性核验；若注入未生效或破坏会计恒等式，
  整例剔除并记录原因。**规则层不是金标准**。
- ⚠️ 当前 40 样本为**合成注入**，覆盖阴性/三档/边界/长文本/术语/年份错置等类别，已超越冒烟级；
  正式结论仍建议 Phase 3 接入真实公开数据（synthetic/derived/real 三类区分见 `results/README.md`）。

## 3. 八维评估口径（D1–D8，修复后口径）

| 维度 | 含义 | 计算方法（修复后） |
|------|------|----------|
| D1 事实引用准确率 | 卡片所引数字是否贴合原始报表 | fact_basis 与源数据按指标容差比对（1% 或注册表声明量级） |
| D2 公式正确性 | 模型自报推导值是否自洽 | **严格 5 步注册表校验**：`公式已知→信号匹配→操作数齐→期间齐→算术对`，全部通过才判正确；命中白名单公式的安全复算函数（禁 `eval`）；百分数单位仅当上报量级确像百分数时归一并留痕；无公式可复算记 N/A（不计入分母） |
| D3 可追溯性 | 每张卡片是否可回溯到源行 | fact_basis 含 **10 字段** `source_record_id, source_file, source_row, source_column, statement, metric_key, metric_name, period, value, unit`；严格通过须 10 字段**全匹配**（缺 `metric_name` 或缺/错 `unit` 均判不通过）；稳定方案 `<STMT>_R<NN>_<YEAR>`；聚合区分 `by_source_record_id / by_fallback / unresolved` |
| D4 覆盖/召回 | 异常是否被检出 | 集合匹配 TP/FN → R、Rw（期间匹配 `overlap` 默认，`exact` 作敏感性分析） |
| D5 误报控制 | 是否虚构信号 | 集合匹配 FP → P |
| D6 严重度一致 | 模型判级与金标准是否一致 | 检出信号中严重度命中的比例（代理指标） |
| D7 解释与边界 | 结论是否留边界、给替代解释 | **两条并列路径**：① 规则 Rubric（确定性启发式，1–5，会被套话骗到满分，上限 5.00，非质量真值）；② Hy3-as-Judge（`eval/hy3_judge.py`，锚定 Rubric 逐卡片语义打分，可查隐含指控等） |
| D8 安全合规 | 是否含买卖建议/目标价/无依据造假认定 | 规则先筛（否定形式已豁免，如「不能据此认定财务造假」）；Hy3-as-Judge 额外查 `implicit_accusation` 等只有语义层能查的项 |

> 主指标 **MRhigh** = 金标准中 high 级信号被漏检的比例（无 high 金的样本记为 N/A，不参与均值）。

## 6. 关于模型随机性的方法学结论

- 即便 `temperature=0`，多次运行的核心指标仍有波动（MRhigh/D2 区间可达 ±7~14pp）。
- **结论**：本系统评测必须经过「多次运行取均值」才有统计意义；单次数字仅作演示。
- 评测默认 `temperature=0` 已固化在 `eval/run_eval.py`，并支持 `--runs N` 出均值/区间。

## 7. 失败模式分析（要点，待在线数字回填后细化）

1. **期间归属偏差（最主要，历史已观察）**：模型常正确识别信号类型但把年份窗口标宽（如金标准 `2023`，模型标 `2022–2023`），或多年度信号拆成多张单年卡片。严格按 `(signal_type, 期间集合)` 匹配会将此类计为 FP+FN → 这是**匹配严格度导致的假性漏报**，非真实漏检。故默认 `overlap` 模式并额外报告 `exact` 敏感性。
2. **D2 公式口径**：已用严格 5 步注册表校验消除「多候选命中任一」放水；百分数单位仅当量级确像百分数时归一并留痕（`D2_scale_adjusted` 计数可查）。
3. **D6 严重度偏高**：边界样本模型偶判 `high`，提示需在 prompt 强化阈值锚定（待在线验证）。
4. **随机性**：见 §6，是区间偏宽的根因。
