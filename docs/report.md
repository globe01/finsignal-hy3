# FinSignal-Hy3 评测报告（首轮真实验证）

> 犀牛鸟开源实战任务 · 基于 Hy3 的上市公司财务异常信号识别与漏报敏感型评估系统
> 评测日期：2026-08-27 ｜ 模型接入：腾讯云 TokenHub / `model=hy3`（OpenAI 兼容 Chat Completions）
> 本文档对应方案 §6、§7、§13；本报告为 9/11 初稿所需的真实验证结论。

---

## 1. 评测目标

本系统的核心关怀是 **「漏报」而非「误报」**：财务报表异常信号一旦被漏检，后果远重于
少量误报。因此主指标采用 **严重异常漏报率 MRhigh**，并以八维评估（D1–D8）刻画模型在
事实、公式、可追溯、覆盖、误报、严重度、解释边界、安全合规上的综合表现（方案 §6.1）。

---

## 2. 数据集构造（14 个样本，方案 §5.4 / §7.3）

| 类别 | 数量 | 说明 |
|------|------|------|
| 阴性对照（清洁公司） | 2 | 金标准为空，验证 D5 误报控制 |
| 注入异常（5 类 × 强度 1/2） | 10 | 在会计恒等式自洽前提下植入偏离 |
| 边界/阈下对照 | 2 | 近阈值植入（强度 ×0.4），验证稳定性 |

- 注入信号类型：`receivables_revenue_divergence`、`inventory_cost_divergence`、
  `goodwill_net_assets_pressure`、`gross_net_margin_divergence`、`cashflow_profit_divergence`。
- **复合样本说明（重要）**：应收/存货/毛利-净利类注入会同时压低经营性现金流，故金标准
  中除目标信号外还会记录 `cashflow_profit_divergence`（方案 §5.4 要求「记录全部触发项」）。
  模型在真实运行中亦稳定检出该复合信号，故评测一致。
- 金标准由规则 Oracle（`eval/rules.py`）从三表独立复算得到，与模型输出解耦。

## 3. 八维评估口径（D1–D8）

| 维度 | 含义 | 计算方法 |
|------|------|----------|
| D1 事实引用准确率 | 卡片所引数字是否贴合原始报表 | fact_basis 与源数据 1% 容差比对 |
| D2 公式正确性 | 模型自报推导值是否自洽 | 用模型自引 fact_basis 操作数独立复算其可能意图的数值，命中即判正确（**定义无关**，避免惩罚「同义不同式」） |
| D3 可追溯性 | 每张卡片是否可回溯到源行 | fact_basis 含有效 source_row 的比例 |
| D4 覆盖/召回 | 异常是否被检出 | 集合匹配 TP/FN → R、Rw |
| D5 误报控制 | 是否虚构信号 | 集合匹配 FP → P |
| D6 严重度一致 | 模型判级与金标准是否一致 | 检出信号中严重度命中的比例（代理指标） |
| D7 解释与边界 | 结论是否留边界、给替代解释 | 启发式 Rubric 1–5（方案 §6.2） |
| D8 安全合规 | 是否含买卖建议/目标价/无依据造假认定 | 规则先筛（否定形式已豁免，如「不能据此认定财务造假」） |

> 主指标 **MRhigh** = 金标准中 high 级信号被漏检的比例（无 high 金的样本记为 N/A，不参与均值）。

## 4. 真实验证结果（Hy3 在线，temperature=0，3 次运行取均值±区间）

> **关键发现**：Hy3 在 TokenHub 当前部署下即使 `temperature=0` 仍有明显输出随机性（见 §6）。
> 因此**单次运行不足以代表模型水平**，以下为 3 次独立运行（各 14 样本）的汇总：

| 指标 | 均值 | 区间(min–max) | 评价 |
|------|------|------|------|
| **MRhigh 严重异常漏报率** | **33.3%** | 28.6% – 42.9% | 主要短板，约 1/3 严重异常被漏报 |
| P 精确率（D5） | 73.6% | 65.0% – 81.7% | 误报可控但偏高 |
| R 召回率（D4） | 69.7% | 60.6% – 74.2% | 覆盖尚可 |
| Rw 加权召回 | 69.3% | 60.2% – 73.9% | 与 R 一致 |
| D1 事实引用准确率 | 92.5% | — | 引数准确，质量高 |
| D2 公式正确性 | 62.4% | 46.3% – 74.2% | 推导稳定性不足，波动大 |
| D3 可追溯性 | 100% | — | 全部可回溯源行 |
| D6 严重度一致 | 61.8% | 56.7% – 66.7% | 判级偏保守/偏高 |
| D7 解释质量（1–5） | 5.00 | 稳定 | 解释充分、边界清晰 |
| D8 安全合规 | 100% | 稳定 | 无买卖建议/目标价/无依据造假认定 |

## 5. 失败模式分析

1. **期间归属偏差（最主要）**：模型常正确识别信号类型，但把年份窗口标宽
   （如金标准标 `2023`，模型标 `2022–2023`），或多年度信号拆成多张单年卡片。
   严格按 `(signal_type, 期间集合)` 匹配（方案 §6.3）会将此类计为 FP+FN。
   → 这是**匹配严格度导致的「假性漏报」**，非真实漏检。
2. **D2 公式定义差**：`gross_net_margin_divergence` 模型常报「净利率变动百分点」，
   而规则 Oracle 的 `measure_x` 为「毛利变动−净利变动」的差值；二者都正确但口径不同。
   → 已用「定义无关的内部一致性」判定，避免误罚。
3. **D6 严重度偏高**：边界样本（如 `cashflow medium`）模型偶判为 `high`。
   → 提示需在 prompt 中强化阈值锚定。
4. **随机性**：见 §6，是 MRhigh/D2 区间偏宽的根因。

---

## 6. 关于模型随机性的方法学结论

- 即便 `temperature=0`，3 次运行的核心指标区间仍达约 ±7%（MRhigh ±7pp，D2 达 ±14pp）。
- **结论**：本系统评测必须经过「多次运行取均值」才有统计意义；单次数字仅作演示。
- 已在本仓库 `eval/run_eval.py` 中将评测默认 `temperature=0` 固化，并建议上报时附 3+ 次运行区间。
