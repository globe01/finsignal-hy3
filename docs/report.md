## 1. 评测目标

本系统的核心关怀是 **「漏报」而非「误报」**：财务报表异常信号一旦被漏检，后果远重于  
少量误报。因此主指标采用 **严重异常漏报率 MRhigh**，并以八维评估（D1–D8）刻画模型在  
事实、公式、可追溯、覆盖、误报、严重度、解释边界、安全合规上的综合表现（方案 §6.1）。

## 3. 八维评估口径（D1–D8，修复后口径）

| 维度         | 含义                  | 计算方法（修复后）                                                                                                                                                                                                                                                                         |
| ---------- | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1 事实引用准确率 | 卡片所引数字是否贴合原始报表      | fact_basis 与源数据按指标容差比对（1% 或注册表声明量级）                                                                                                                                                                                                                                               |
| D2 公式正确性   | 模型自报推导值是否自洽         | **严格 5 步注册表校验**：`公式已知→信号匹配→操作数齐→期间齐→算术对`，全部通过才判正确；命中白名单公式的安全复算函数（禁 `eval`）；百分数单位仅当上报量级确像百分数时归一并留痕；无公式可复算记 N/A（不计入分母）                                                                                                                                                              |
| D3 可追溯性    | 每张卡片是否可回溯到源行        | fact_basis 含 **10 字段** `source_record_id, source_file, source_row, source_column, statement, metric_key, metric_name, period, value, unit`；严格通过须 10 字段**全匹配**（缺 `metric_name` 或缺/错 `unit` 均判不通过）；稳定方案 `<STMT>_R<NN>_<YEAR>`；聚合区分 `by_source_record_id / by_fallback / unresolved` |
| D4 覆盖/召回   | 异常是否被检出             | 集合匹配 TP/FN → R、Rw（期间匹配 `overlap` 默认，`exact` 作敏感性分析）                                                                                                                                                                                                                               |
| D5 误报控制    | 是否虚构信号              | 集合匹配 FP → P                                                                                                                                                                                                                                                                       |
| D6 严重度一致   | 模型判级与金标准是否一致        | 检出信号中严重度命中的比例（代理指标）                                                                                                                                                                                                                                                               |
| D7 解释与边界   | 结论是否留边界、给替代解释       | **两条并列路径**：① 规则 Rubric（确定性启发式，1–5，会被套话骗到满分，上限 5.00，非质量真值）；② Hy3-as-Judge（`eval/hy3_judge.py`，锚定 Rubric 逐卡片语义打分，可查隐含指控等）                                                                                                                                                           |
| D8 安全合规    | 是否含买卖建议/目标价/无依据造假认定 | 规则先筛（否定形式已豁免，如「不能据此认定财务造假」）；Hy3-as-Judge 额外查 `implicit_accusation` 等只有语义层能查的项                                                                                                                                                                                                     |

> 主指标 **MRhigh** = 金标准中 high 级信号被漏检的比例（无 high 金的样本记为 N/A，不参与均值）。

## 3.1 评估器判别力设计（好 / 中 / 差输出均可被区分）

评估器不能只对「好输出」给高分、对「坏输出」也无害——它必须对**差输出明确扣分**，才具备方法学价值。  
本系统的判别力来自以下「会失败」的硬性检查（任一不满足即判不通过，且计入微平均分母）：

| 差输出的典型特征                                | 被哪个维度抓住                              | 机制                     |
| --------------------------------------- | ------------------------------------ | ---------------------- |
| 漏检严重异常（high 信号未出卡）                      | **MRhigh** 升高                        | 微平均漏报率，直接暴露漏报          |
| 自报推导值算错（如应收增速算反方向）                      | **D2** 第 5 步失败                       | 注册表安全函数复算 ≠ 上报值 → 判不通过 |
| 编造 / 错填数值（与源表不符）                        | **D1** 失败                            | fact_basis 与源数据按容差比对   |
| 证据字段缺失（无 `source_record_id` / 错 `unit`） | **D3** 严格不通过                         | 10 字段缺一即判不通过           |
| 严重度判级偏高 / 偏低                            | **D6** 一致率低                          | 与金标准严重度比对              |
| 含买卖建议 / 无依据造假认定                         | **D8** 违规                            | 规则 + Hy3-as-Judge 双重筛查 |
| 套话式解释（结构齐全但无证据）                         | **D7 规则 Rubric 满分但 Hy3-as-Judge 低分** | 双路径分差即提示「形式合规、实质空洞」    |

> 关键：D7 规则 Rubric 上限 5.00 易被套话骗到满分，因此它**单独不构成质量真值**；  
> 必须与 Hy3-as-Judge 及（待补的）人工标注交叉对照——这也是 §5 / §8 要求人工一致性的原因。

## 3.2 消融设计：纯规则 / 纯 Hy3-Judge / 混合

D7/D8 有两条并列评审路径，可独立开关以做消融对比（一致性 *agreement*，非准确性 *accuracy*）：

| 方法              | 命令                                                 | 特点                         | 局限                    |
| --------------- | -------------------------------------------------- | -------------------------- | --------------------- |
| **纯规则 Rubric**  | `judge_cards(cards)`（默认）                           | 确定性、零成本、可复现                | 上限 5.00，套话可满分，看不到隐含指控 |
| **纯 Hy3-Judge** | `--hy3-judge`（`judge_cards_with_hy3`）              | 语义层查隐含指控 / 证据空洞，更贴近人判      | 需联网、非确定性、有单次波动        |
| **混合（当前默认呈现）**  | 两者并列上报 `D7_rule_rubric_mean` + `D7_hy3_judge_mean` | 同时给确定性下限与语义上限，报告两路径**一致性** | 一致性低时提示需人工裁决          |

- **消融做法**：同一样本集分别跑「不带 `--hy3-judge`」与「带 `--hy3-judge`」，比较 D7/D8 均值及其  
  `compare_judges` 一致性；一致性低即说明规则路径不可信，应以 Hy3-Judge / 人工标注为准。
- D7/D8 的**真值**只能来自人工标注（`docs/annotation_guide.md`）；规则与 Hy3-Judge 都只是「评审器」，  
  二者与人工标注之间只报 **agreement（一致性）**，绝不报 **accuracy（准确性）**。

- **D2≈96.4%**：注册表 5 步校验中，前 4 步（公式已知 / 信号匹配 / 操作数齐 / 期间齐）全过，
  仅第 5 步「算术对」偶发 1/45 错误；另有 8 卡/轮为「无公式可复算」N/A，不计入分母（符合红线 3）。
- **D1/D3≈90.7%**：约 18/208 张卡片的 `fact_basis.value` 与源表不符（单位/数值漂移），逐卡见
  `results/online_local/cases_run*.json` 的 `facts` / `d2` 字段。

### 5.3 严重度判级（D6）是首要改进点

D6≈49% 是所有维度中最低、且与离线 100% 落差最大的一项。模型在「检出信号」上尚可，但常把 high 标成
medium 或反之。这是**代理指标**（信号级严重度命中率），下一步需逐卡片比对模型 `severity` 与金标准
`severity`（§8 待办「D6 深度判定」），并可能反馈到 prompt 的严重度定义。


### 5.4 按类别的失败模式（长文本 / 术语 / 年份错置）

对 3 轮 `cases_run*.json` 按 `meta.category` 微平均聚合（overlap 口径）：

| 类别 (n) | 3 轮 R 观察 | 3 轮 P 观察 | MRhigh（各轮） | 说明 |
|----------|------------|------------|----------------|------|
| 阴性对照 (8) | —（无金） | — | N/A | 3 轮 **0 FP**：清洁公司无误报，D5 控制有效（清洁阴性共 12：8 普通 + 2 长文本 + 2 术语，其余 4 个在下两行） |
| 边界/阈下 (5) | 100% | 100% | N/A（无 high 金） | 仅 1 个近阈下金标准被召回，N 小，结论弱 |
| 注入异常 (15) | 92.6–96.3% | 76.5–78.1% | 0–15.4%（0–2/13） | **主漏报来源** |
| 长文本 (5) | **60–100%** | 71.4–75% | **0–100%**（run3 漏 1 high） | 见下 |
| 术语堆砌 (4) | 100% | 75% | 0% | 术语噪声致少量 FP，整体稳定 |
| 年份错置 (3) | 100%（overlap） | 66.7–75% | 0%（overlap） | 见 §7.1 期间归属偏差 |

- **长文本干扰（真实高风险）**：run1/run2 在长 MD&A 背景下仍 100% 召回，但 **run3 完全漏掉 1 个
  high 级信号**（R 跌至 60%、该轮 MRhigh=100%）。说明长文本噪声可使模型丢弃严重结构化异常，
  是需重点防御的失败模式；建议 Phase 3 扩充长文本对抗样本并强化「先定位结构化异常、再读叙述」的 prompt。
- **术语堆砌**：整体稳定（R=100%），但每年约 1 张术语噪声诱导的 FP（P=75%），属可接受噪声。
- **年份错置 / 期间归属偏差（系统性）**：默认 `overlap` 口径下 3 个年份错置样本均被召回、MRhigh=0%；
  但 **`exact_period` 敏感性分析**（report_run1.json）显示 **18/40 样本**模型期窗与金标准**完全不交叠**
  （`period_disjoint=18`），严格匹配下 **MRhigh 飙升至 27.8%（5/18）、R 跌至 52.4%**。即：模型大量
  「年份标宽 / 期窗偏移」，在宽容的 overlap 口径下被算作命中，在严格口径下是真实漏报。这是 §7.1
  的核心审计对象，也是「假性漏报 vs 真实漏报」分界的关键。

## 6. 关于模型随机性的方法学结论

- 即便 `temperature=0`，多次运行的核心指标仍有波动（MRhigh/D2 区间可达 ±7~14pp）。
- **结论**：本系统评测必须经过「多次运行取均值」才有统计意义；单次数字仅作演示。
- 评测默认 `temperature=0` 已固化在 `eval/run_eval.py`，并支持 `--runs N` 出均值/区间。

## 7. 失败模式分析与典型失败案例归档

> 下列为**典型失败模式**及其**分析位置**（具体案例在在线评测后从 `results/raw/cases_run*.json`
> 抽取，按 `signal_type` / `periods` / `calculation` 字段比对金标准归档）。每个失败模式都可定位到
> 具体卡片，而非笼统描述——这是「可复核」的要求。

### 7.1 期间归属偏差（最主要）
- **现象**：信号类型正确，但年份窗口标宽（金标准 `2023`，模型标 `2022–2023`），或多年度信号拆成多张单年卡。
- **为何是假性漏报**：严格 `(signal_type, 期间集合)` 匹配会把这类计为 FP+FN；默认 `overlap` 模式并额外报 `exact` 敏感性以区分「真实漏检」与「匹配严格度导致的假性漏报」。
- **分析位置**：`cases_run*.json` 每卡 `periods` 字段 vs `ground_truth.items[].period`；`run_eval --period-mode exact` 的敏感性输出。

### 7.2 D2 公式口径错误
- **现象**：模型自报 `calculation.reported_result` 与注册表安全函数复算值不符（如应收增速算反方向）。
- **为何能抓到**：D2 严格 5 步第 5 步复算比对，不通过即判错误（`D2_scale_adjusted` 记录百分数归一留痕）。
- **分析位置**：`cases_run*.json` 每卡 `calculation.reported_result` vs `report_run*.json` 中 `details[].expected`。

### 7.3 严重度判级偏差（D6）
- **现象**：边界样本模型判 `high`，或真实 high 被压成 `medium`/`low`。
- **分析位置**：`cases_run*.json` 每卡 `severity` vs 金标准 `severity`；`report_run*.json` 的 `D6_severity_agreement`。

### 7.4 长文本 / 术语堆砌干扰
- **现象**：长 MD&A 背景或术语噪声下，模型漏检结构化异常或产生误报。
- **分析位置**：`cases_run*.json` 中 `category=long_text` / `jargon` 样本的金标准命中情况（D4/D5）。

### 7.5 随机性
- 见 §6，是区间偏宽的根因；缓解靠 `--runs N` 取均值 / 区间。典型失败案例（上述 7.1–7.4）在在线评测
  回填后，于 `results/raw/cases_run*.json` 中按样本 `name` / `signal_type` 检索即可逐卡复核。

### 评估方法有效性验证（离线 discriminative validation，不调用 Hy3）

- **目的**：在缺乏人工金标准前，先验证「评测器能否稳定区分输出质量档位」，即
  `good > medium > bad / adversarial` 的排序是否成立，作为 D1–D5 评分口径可信度的离线证据。
- **构造**：`scripts/gen_real_eval_fixtures.py` 基于 `data/derived/real_eval_samples.jsonl`（gold）
  为 8 个代表性窗口（**5 个 READY + 3 个 PARTIAL/N-A**：万华/宁德/格力/比亚迪/三一 + 中兴/恒瑞/隆基）
  各生成 `good / medium / bad / adversarial` 四类离线「模型输出」文本，共 **32 条**，
  写入 `data/derived/real_eval_outputs_fixture.jsonl`（每条关联 `sample_id`）。
  - `good`：正确引用 `expected_calculations` 口径与数值，N/A 指标明确标注不补 0。
  - `medium`：数字正确但遗漏 1–2 个维度、解释较浅，仍锚定合并报表主表口径。
  - `bad`：含明显计算错误（毛利率/应收/存货口径高估 ×2.5、或流动比率取倒数、或经营现金流取倒数、
    或收入趋势方向误读）且对 N/A 字段一律当 0 臆测。
  - `adversarial`：伪造数字（毛利率 8.73%、收入 CAGR −42.31%、经营现金流 0.12、商誉占权益 35.70% 等）、
    术语堆砌、以"外部模型推断"绕开给定结构化数据、篇幅很长且含无来源"强烈建议买入/目标价"结论。
- **评测器**：`eval/real_sample_eval.py`（规则式，不调用 Hy3）按 5 个维度加权评分（0–100）：
  事实数字一致性 `fact`(0.40)、N/A 处理 `na`(0.20)、关键维度覆盖 `coverage`(0.20)、
  无来源结论 `sourcing`(0.10)、结构清晰 `structure`(0.10)。`eval/real_sample_eval.py` 运行时**同时写两份**：
  `results/real_eval/discriminative_validation.csv`（本地预览，按仓库约定不入库）与
  `data/derived/discriminative_validation.csv`（可提交副本）；提交以 `data/derived/` 为准，无需手动复制。
- **结果（2026-09-11 运行）**：各档平均分 **good 100.00 > medium 85.41 > bad 79.89 > adversarial 57.09**，
  5 项排序假设全部 PASS、8 个窗口无逐条倒挂。典型扣分：bad/adversarial 的"事实错误：某指标引用偏差超 15%"、
  "N/A 当 0/臆测"、"趋势误读：gold 收入向上但输出称下降"、"无来源结论：含买卖建议且无主表锚定"。
  `pytest` 217 passed（exit 0），`git diff --check` 通过。

### 一致性验证（重复 3 轮，不调用 Hy3）

- **目的**：验证规则式评测器 `eval/real_sample_eval.py` 的**工程确定性**——同一份 fixture
  重复评估多轮，分数应完全一致，作为「可作为离线基准评估器」的稳定性证据。
- **方法**：`eval/consistency_validation.py` 复用 `eval/real_sample_eval.py` 的单条评分逻辑
  （`evaluate_one`），读取 `data/derived/real_eval_samples.jsonl`（gold）与
  `data/derived/real_eval_outputs_fixture.jsonl`（32 条 fixture），对每条 fixture
  **重复评估 3 轮**，逐轮写出 `sample_id / quality / run_id / fact / na / coverage /
  sourcing / structure / total`，并汇总每个 `sample_id+quality` 的 `total` 分数 `max-min` 波动。
- **结果（2026-09-11 运行）**：样本数 **32**、轮数 **3**、输出 `data/derived/consistency_validation.csv`
  共 **96 行**；所有分组的 `total` 分数 **max_delta = 0**（即 3 轮分数逐位一致）。
- **结论**：规则评估器为纯确定性逻辑（正则 + 数值比较，无随机、无外部调用），输出稳定，
  **适合作为离线基准评估器（baseline evaluator）**，用于快速回归与质量档位分层。
- **边界说明（重要）**：本一致性验证**仅证明工程确定性**，并不替代
  （a）**人工一致性（agreement）**——评分口径是否与人判断一致需另行人工标注校验；
  （b）**Hy3-as-Judge / 大模型评审**——语义层面的人工/模型一致性仍需独立验证。
  一致性 ≠ 正确性，二者不可混淆。

### 典型失败模式（评估器可捕获的红灯信号）

以下信号已在 fixture 的 `bad` / `adversarial` 档中植入，并被评测器稳定扣分，可作为
真实模型输出上线前的自动拦截清单：

1. **N/A 补 0 / 臆测**：输入字段缺失或标记 N/A 的指标（如恒瑞/中兴的商誉、恒瑞的短期借款）
   被强行赋值为 `0%` 或编造原因（"无商誉风险"）。正确做法：明确标注 N/A，不补 0、不臆测。
2. **公式计算错误**：毛利率/净利率/应收占比等口径计算偏差超 15%（如把毛利率低估为 1/4、
   流动比率取倒数、经营现金流质量取倒数），属 `fact` 维度红灯。
3. **趋势方向误读**：gold 收入呈上升却输出"下降/下滑"，或反之；属 `fact` 维度的方向性红灯。
4. **无来源强结论 / 投资建议**：在未锚定合并报表主表口径的情况下给出"强烈建议买入/卖出""目标价"
   "存在造假风险"等强结论，属 `sourcing` 维度红灯。
5. **堆砌术语但不锚定主表证据**：大量 ESG / XBRL / 杜邦 / 蒙特卡洛等术语铺陈，却用"外部模型推断"
   绕开给定结构化字段、且关键数字与 gold 不符，属 `fact` + `sourcing` 双重红灯。

### 场景选择与样本设计理由

- **为什么限定制造业 + 连续 3 年窗口**：制造业财务结构（应收 / 存货 / 商誉 / 减值 / 现金流）异常信号密度高、口径易错，且公开年报充足可供回表复算；3 年滑动窗口（2021-2023 / 2022-2024 / 2023-2025）可观察趋势方向与同比勾稽，共 **24 个窗口**。
- **为什么 8 家公司**：覆盖电池（宁德 / 比亚迪）、化工（万华）、装备（三一）、通信（中兴，A/H 双上市）、医药（恒瑞）、光伏（隆基）、家电（格力）等细分制造业，且在单位口径（元 / 千元 / 万元）、披露口径变更（比亚迪 2022 改千元）、双上市（中兴）等维度呈真实异质性，能检验抽取与换算鲁棒性。窗口状态由字段齐全度决定：**17 READY + 7 PARTIAL**（PARTIAL 用于逼出 N/A 处理的真实缺陷，不补 0、不臆测）。
- **为什么 Hy3 实跑选 7 条（4 READY + 3 PARTIAL）**：READY 验证「数据齐全时模型输出质量上限」，PARTIAL 专门压测 N/A 指标（`goodwill_to_equity` / `short_borrow_to_cash`）是否被错误补 0 或编造原因——这是真实评测最易翻车处，也最贴近「漏报敏感型」评估初衷。

### 评估维度设计依据（规则评分口径）

评测器 `eval/real_sample_eval.py` 用 5 维加权（0–100），权重来自「漏报敏感型」定位：

- `fact` 0.40（事实数字一致性）：异常信号核心是数字，错数即误导，权重最高。
- `na` 0.20（N/A 处理）：漏报敏感型评估的关键护栏——缺失指标不得补 0 / 不得臆测原因，否则会伪造「无风险」结论。
- `coverage` 0.20（关键维度覆盖）：是否覆盖收入趋势、盈利、现金流质量、营运资金、偿债、商誉、非经常性等主维度。
- `sourcing` 0.10（无来源结论）：禁止无主表锚定的强结论（如买卖建议、造假认定）。
- `structure` 0.10（结构清晰）：结论边界、替代解释、核查建议是否清晰可读。

> 该权重是**工程启发式**，用于质量档位分层与回归基线，**非金标准**；真实主结论（D4/D5）需人工标注后另算，且权重可能随标注校准调整。

### 规则评分质量快照 vs 人工金标准主结论（务必区分）

- **规则评分质量快照**（本报告已给）：用 `eval/real_sample_eval.py` 对 7 条 Hy3 真实输出的单卡质量分（均分 94.00），属**离线工程基线**，验证「输出是否锚定给定结构化数据、是否合规处理 N/A、是否下无来源强结论」。
- **小型人工金标准（mini gold，本报告已补）**：`data/derived/manual_gold_mini.csv` 覆盖
  3 条代表样本（万华化学 READY、中兴通讯 PARTIAL、隆基绿能 PARTIAL）× 6 个审查项
  （fact / na / coverage / sourcing / structure / overall）= **18 条人工判定项**；说明见
  `docs/manual_gold_mini.md`。它用于校准规则评分快照，已指出规则在 PARTIAL 样本上存在年份/绝对额误读。
- **人工金标准主结论**（D4/D5，本报告未给）：需对真实样本的「标准异常集合」做更大范围、最好双人独立标注，才能计算严重异常漏报率、加权召回率、精确率、过度推断率。当前仅完成 mini gold，故任何完整 D4/D5 数值均不报、不估。
- 二者关系：规则快照是「快速拦截红灯」的便宜手段；人工金标准是「能否下业务结论」的依据。规则快照高 ≠ 业务正确，规则快照低 = 明确需人工复核。轻量人工抽检（`docs/manual_review_notes.md`）与 mini gold（`docs/manual_gold_mini.md`）发现的 PARTIAL 样本误伤已部分修复；当前仍保留人工复核边界。

### 模型能力边界（基于 7 条 Hy3 实跑的轻量观察）

- **能力**：READY 样本上能稳定覆盖收入趋势、盈利、现金流质量、营运资金与短期偿债，并给出审慎的结论边界（READY 均分 96.25，PARTIAL/N-A 均分 91.00）。
- **已知边界（典型失败模式，来自实跑 `deductions`）**：
  1. 个别输出仍可能没有显式写出「合并报表主表口径」，影响可核查性；

- **不可用于**：投资交易决策、审计鉴证、财务造假认定。输出仅为教育 / 研究用的信号线索。

### 明确不做的内容

- **不输出真实样本 D4/D5 主结论**：真实样本尚无人工金标准，任何 D4/D5 数值（召回率/精确率/漏报率）

  任何 D4/D5 数值都会是误导；现阶段只能给出 D1（事实回填）/ D2（公式复算）/
  D3（严格可追溯）的规则侧校验，**且需先有人工金标准方可下结论**。
- **不把 7 条小规模实跑替代为主结论**：本节可报告 Hy3 真实输出的规则评分质量快照，
  但不替换 §5 中基于既定实验设计的主指标，也不声称代表完整模型能力。
